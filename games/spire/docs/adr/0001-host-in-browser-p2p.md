# Хост сессии работает в браузере игрока, связь — WebRTC P2P

Игра публикуется на GitHub Pages, где нельзя запустить серверный код, а владелец хочет держать всё «там же» без отдельного хостинга и аккаунтов. Поэтому создатель сессии сам выступает авторитетным хостом: его браузер ведёт симуляцию, а гости соединяются с ним напрямую по WebRTC (звезда). Для установки соединения используется публичный бесплатный сигнальный канал, без собственного бэкенда.

## Рассмотренные варианты

- **Отдельный сервер (Cloudflare Workers + Durable Objects, Fly.io)** — честная авторитетность и сессия переживает уход любого игрока, но это второй хостинг с деплоем, аккаунтом и лимитами бесплатного тарифа.

## Последствия

- Уход хоста завершает сессию, если не предусмотрена передача хоста.
- Часть игроков за симметричным NAT не соединится без TURN-ретранслятора.
- Хост технически может жульничать; для игры с друзьями это приемлемо.
- Сетевой транспорт прячется за собственным интерфейсом, чтобы при необходимости перейти на отдельный сервер без переписывания игры.
- Набор Nostr-реле задан явно (`RELAYS` в `scripts/net.ts`): выборка Trystero по умолчанию для нашего appId включала недоступные реле, а часть популярных реле отклоняет такие события (лимиты частоты, «web of trust»). Если сессии перестанут находиться, первым делом проверяется этот список.
- Хост считает матч по тикеру в Web Worker: таймеры фоновой вкладки браузер замедляет до 1 Гц, и без этого игра у гостей замирала бы, когда хост переключился в другое окно.
- Комнату лобби страница открывает один раз и не покидает до закрытия, а повторный вход в комнату сессии ждёт завершения прошлого `room.leave()`. Trystero делит WebRTC-соединения между комнатами, и после выхода и повторного входа в ту же комнату объявления переставали доходить: в 0.1.0 после первой сессии новые сессии не появлялись в списке.
