# Shelter Engine · While the light is on

**While the light is on** · [Играть в браузере](https://gadaev-sergey.github.io/While-the-light-is-on/) · [Репозиторий](https://github.com/gadaev-sergey/While-the-light-is-on)

**[GDD — источник истины о замысле, лоре и устройстве уровней](GDD.md).** README описывает текущую реализацию и её запуск.

2.5D прототип дома в разрезе с объёмным окружением и плоским героем, ориентированный на пространственные принципы This War of Mine. Два жилых этажа, подвал, шесть помещений, лестницы и дворовая территория. Из предыдущей игры сохранён разработчик с пузиком, очками, худи и клавиатурой. Прежний лор о багах, офисные уровни и система суперкомбинаций не используются. Актуальная история происходит в 2034 году после Третьей мировой войны; её вступление с выходом из бункера и поиском убежища пока не реализовано.

## Запуск

Дважды щёлкните **Start Shelter Engine.command** на macOS. Откроется менеджер независимых проектов. Дальнейшая работа — через окна редактора: создание, библиотека, планировка, пробная игра, сохранение и Web-сборка. [Инструкция](docs/engine/EDITOR.md) · [Архитектура и SDK](docs/engine/SDK.md) · [Отчёт приёмки](docs/engine/ACCEPTANCE.md).

Для разработчика:

Node.js 22.14+ и npm:

```sh
npm install
npm run dev
```

Откройте http://127.0.0.1:5173/. Корневой адрес открывает менеджер проектов. **Открыть пример** загружает отдельный проект дома; **Играть** запускает его в редакторе. `npm run build` проверяет типы и собирает приложение редактора. Самостоятельную игру выпускает кнопка **Собрать игру** или разработческая команда `npm run build:game -- games/while-the-light-is-on`. Для готовой игры локальная служба, аккаунт и API-ключи не нужны.

## Публикация на GitHub Pages

[Учёт токенов и моделей](docs/engine/AI-USAGE.md): **Проект → ИИ · статистика разработки**.

**[Shelter Arcade — каталог игр](https://gadaev-sergey.github.io/shelter-arcade/)** · [Правила выпуска игр и патчей](docs/engine/RELEASING.md) · [Навык движка](skills/shelter-game-release/SKILL.md).

В редакторе откройте нужный проект и нажмите **Опубликовать ↗** (также **Сборка → Опубликовать на GitHub Pages**). Укажите свой репозиторий, подключите GitHub и нажмите **Опубликовать игру**. Движок сохранит проект, соберёт Release, отправит готовую игру в `gh-pages` и настроит Pages. После развёртывания появятся ссылка на игру и кнопка её копирования. [Пошаговая инструкция и подключение GitHub](docs/engine/EDITOR.md#публикация-на-github-pages).

Публикуется открытый проект с выбранными сценами. Настройки репозитория запоминаются отдельно для каждого проекта; токены в проект и на диск не записываются. Основная ветка не изменяется, а существующая ветка `gh-pages` с другим проектом не перезаписывается.

Для автопубликации исходного примера из кода сохранён workflow `.github/workflows/pages.yml`: при push в `main` или ручном запуске он устанавливает зависимости, проверяет механику и публикует `dist/`. В Settings → Pages источник публикации должен быть **GitHub Actions**. Секреты вручную добавлять не нужно: используются стандартные права `GITHUB_TOKEN`. Если сайт уже публикуется из ветки через редактор, workflow пропускает сборку, чтобы не заменить выбранную игру примером.

`npm run build:pages` включает префикс `/While-the-light-is-on/` для HTML, CSS и всех игровых изображений. Обычная локальная разработка продолжает работать по корневому адресу.

Для проверки этой сборки запустите `npm run preview -- --base /While-the-light-is-on/`, а в другом терминале — `npm run test:deployment`. Проверка использует Google Chrome и проверяет загрузку всех 12 PNG, отсутствие ошибок, взаимодействия, фонарик, план и мобильный экран. Опубликованный сайт можно проверить командой:

```sh
npm run test:deployment -- https://gadaev-sergey.github.io/While-the-light-is-on/
```

## Текущая локация

Дом теперь отображается в настоящем 3D на Three.js / WebGL2: два жилых этажа, подвал, шесть помещений и двор. Стены, перекрытия, наклонная крыша, двери, оконные рамы, повреждения, лестницы и мебель имеют геометрию и глубину. Персонаж и пёс остаются плоскими анимированными спрайтами внутри сцены. Планировка, движение, взаимодействия и существующие сохранения сохранены.

Материалы здания используют исходный `materials.png`. Шкаф, ящики, раковина и кровать — 3D-модели из [`models/`](models/README.md): они собраны в Blender по спрайтам `interior-front.png`, текстуры запечены, игра загружает их как GLB. Остальная мебель пока собрана из простых деталей. Дальний квартал остаётся изображением за домом.

Камера всегда смотрит прямо; вращение и приближение в игре отключены. В редакторе настраиваются проекция, FOV 15–100°, высота кадра, расстояние, центр, слежение за героем, плавность и границы видимости. «Кадр игры» проверяет композицию в широком или телефонном формате с направляющими; выход возвращает рабочий ракурс. Движение остаётся боковым, по этажам и лестницам.

Солнце, ночной свет, фонарик и питание влияют на 3D-материалы. У фонарика и направленного наружного света есть карты теней; физические проёмы пропускают свет. Для читаемости первого 3D-прототипа оставлена общая рассеянная подсветка: полностью локальный рассеянный свет из окон ещё не реализован. Воздушная дымка использует глубину сцены и карты теней. Объекты скрываются по существующему геометрическому обзору, вне обзора изображение слегка размывается. Чёрные срезы рисуются отдельным чётким проходом.

[Устройство 3D-сцены, ограничения и проверки](docs/base/RENDERING-3D.md). Предыдущая Canvas-отрисовка сохранена в `renderer.ts` для сравнения и её регрессионных тестов; основной запуск использует `renderer-3d.ts`.

## Основные механики

- **Исследование.** A/D перемещают героя; W/S включают лестничный переход. Щелчок по помещению строит маршрут через лестницы. Закрытые двери блокируют движение и обзор.
- **Двери.** При подходе к закрытой двери герой останавливается и берётся за ручку. Открытая дверь закрывается одним нажатием E, без позы у ручки и панели выбора. E открывает дверь, Q наклоняет героя к скважине и даёт узкий обзор, Esc или шаг назад прекращают взаимодействие. Есть поддержка сюжетных замков; в текущем доме двери не заперты. Взгляд через скважину не пропускает фонарик за полотно.
- **Туман и фонарик.** Вне геометрического обзора сцена размывается, важные предметы и пёс скрыты. Фонарик лишь добавляет свет: он не расширяет обзор и не создаёт свечения вокруг героя. Сплошные перекрытия и закрытые двери отсекают и обзор, и свет. Лестничные проёмы пропускают оба между этажами, сохраняя переднюю кромку пола.
- **Время суток.** Часы сверху позволяют выбрать утро, день, вечер, ночь или точное время. Есть автоматическая смена. Направленный наружный свет учитывает тени геометрии; общая рассеянная подсветка пока упрощена. Ручной выбор останавливает часы.
- **Ночное небо.** Луна и звёзды появляются в сумерках. Наружное освещение становится слабым и холодным, фонарик освещает объёмные поверхности. Небо и квартал остаются за домом.
- **Повреждения.** Проломы на заднем плане и в плоскости движения различаются в данных. Вид через заднюю стену не даёт возможности пройти сквозь соседние перекрытия.
- **Припасы во дворе.** Ящик обыскивается один раз, из бочки можно набрать воду дважды. Действия прерываются движением и выдаются только по завершении таймера.
- **Сохранения.** Версия 3 хранит состояние дверей и повреждений, найденные вещи, исследованные комнаты, героя и режим часов. Ключ `shelter-base-v1` оставлен для миграции прежних сохранений: удалённые предметы и свет от старого генератора не восстанавливаются.
- **Предметы дома.** Можно обыскать ящики и шкаф, набрать воду, отдохнуть, сделать бинт на верстаке и запустить генератор в подвале за 2 детали и предохранитель. Эти действия используют прежние тестовые правила; окончательный баланс ещё не утверждён.

2.5D теперь сочетает объёмную WebGL-локацию с плоскими персонажами. Симуляция остаётся независимой от DOM, навигация — по этажам и лестницам. Для запуска нужен браузер с WebGL2. В dev-сборке `window.__BASE__` предоставляет копию состояния `snapshot()`, проекцию `projection(x, y)` и диагностические значения рендера `rendering()`; API отсутствует в production.

## Проверки и дальнейшая работа

```sh
npm test
npm run build
npm run test:engine
npm run test:e2e
npm run test:engine:e2e
```

Тесты проверяют сборку нескольких домов, изменение этажности, геометрию проёмов, движение и свет, миграцию сохранений, порядок слоёв по пикселям и живой ввод в Chrome. Браузерные тесты используют установленный Google Chrome. Полный набор `test:e2e` проверяет игру A и редактор; `test:engine:e2e` создаёт и переносит нейтральный проект только через интерфейс. Второй набор сам запускает редактор на порту 5174 или использует уже запущенный. Снимки и отчёты находятся в `artifacts/engine/`.

[Визуальные ориентиры](docs/base/REFERENCES.md), [новые ассеты](docs/base/ASSETS.md), [контракты расширения](docs/base/EXTENDING.md).

Масштаб 3D-сцены и принятые габариты: [реестр размеров](docs/base/DIMENSIONS.md). Эталон — герой 178 см; двери, мебель и лестница задаются в метрах в `games/while-the-light-is-on/scripts/game/dimensions.ts`.

## Редактор — Shelter Engine 0.4

Проекты разделены на диске; ядро и интерфейс не импортируют код дома. Сцены, модели, библиотека, комнаты, свет, камера, готовые компоненты и выпуск игры доступны через интерфейс. Сохранение записывает проект на диск, а пробная игра использует отдельное состояние. Семантическая планировка обновляет геометрию, движение и проходы.
