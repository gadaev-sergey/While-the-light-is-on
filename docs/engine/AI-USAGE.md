# Расход токенов на разработку игры

В редакторе: **Проект → ИИ · статистика разработки**. Окно показывает общее число токенов, модели и их доли, вход, кэш, выход и рассуждения. Пока оно открыто, данные синхронизируются каждые 5 секунд. В карточках Shelter Arcade отображается снимок итогов на момент публикации каталога.

В начале каждого хода работы Codex над игрой:

```sh
npm run usage:begin -- games/lumen
```

Команда использует текущий `CODEX_THREAD_ID` и последний `turn_context` его журнала. Привязывается весь текущий ход, включая уже потраченные в его начале токены; остальные ходы общего чата не добавляются. Повторный вызов безопасен. Для нового хода, другой модели, продолжения или отдельного агента нужна новая привязка. Для новой игры сначала создайте проект. Общая разработка движка и каталога в расход отдельной игры не включается.

В конце работы и для ручного обновления:

```sh
npm run usage:sync -- games/lumen
```

Для подтверждённой истории можно явно указать `--thread UUID --turn UUID` в `usage:begin`. Не угадывайте соответствие чата игре. Для «Люмена» и «Периметра» импортированы ходы исходной разработки из сохранившихся журналов; это учтённые этапы, а не доказательство полноты всей истории, общих ресурсов и последующих публикаций. Для старого прототипа без привязанных данных отображается отсутствие статистики.

## Claude Code

В сеансе Claude Code та же команда `npm run usage:begin -- games/<id>` берёт `CLAUDE_CODE_SESSION_ID` и привязывает текущий ход (последний `promptId` журнала). Для прошлых ходов: `--thread <ID сеанса> --turn <promptId> --claude`. Источник — `~/.claude/projects/*/<ID сеанса>.jsonl` (или `CLAUDE_CONFIG_DIR`).

Каждый ответ API учитывается один раз по `message.id` (Claude Code повторяет usage в строке каждого блока содержимого). Вход = `input_tokens` + `cache_creation_input_tokens` + `cache_read_input_tokens`; кэш — `cache_read_input_tokens`; рассуждения — `output_tokens_details.thinking_tokens` внутри выхода. Записи `<synthetic>` (заглушки ошибок без обращения к модели) пропускаются. В журнале расхода такой источник помечен `agent: "claude"`.

## Методика

- Источник — локальные JSONL Codex в `sessions` / `archived_sessions` внутри `CODEX_HOME` (по умолчанию `~/.codex`). Читаются только явно привязанные журналы. Авторизация API не нужна.
- Используются отдельные `token_usage_record.usage`, а не сумма нарастающих итогов `thread_token_usage` или повторяющихся `token_count`. Одинаковый response ID считается один раз; унаследованные записи другого чата исключаются. Расход вызовов инструментов отражается в токенах модели, если он входил в её запрос; отдельные тарифы инструментов здесь не учитываются.
- Название модели — поле модели записи, если оно есть, иначе соответствующий `turn_context` и известное событие перенаправления. Если определить модель невозможно, расход остаётся в категории «Модель не определена». При скрытом перенаправлении, не отражённом в журнале, доступна лишь записанная модель.
- Всего = вход + выход. Кэш — подмножество входа, рассуждения — подмножество выхода. Поэтому миллионы токенов возможны при многократной передаче большого контекста. Эти числа не равны стоимости, лимитам аккаунта, уникальным словам или количеству написанного кода.
- Доля модели = её токены / все учтённые токены. Округление до десятых распределяет остаток так, чтобы сумма была 100%.
- Последний ответ появляется после завершения запроса; следующая синхронизация включает его. Статический каталог обновляется при выпуске. Отсутствие данных показано отдельным состоянием, а не нулём. При недоступном журнале ранее учтённые числа сохраняются с предупреждением в редакторе.

## Хранение

`games/<id>/settings/ai-usage.json` содержит идентичность проекта, привязки ходов и обезличенные счётчики запросов. ID ответов хешируются; текста сообщений, вызовов инструментов и рассуждений нет. `.shelter-cache/usage-bindings.json` предотвращает назначение одного хода двум играм в одном рабочем пространстве. Блокировка на диске сериализует запись CLI и редактора. При аварийном завершении процесса оставшийся `.shelter-cache/usage.lock` можно удалить, убедившись, что синхронизация больше не выполняется.

Переносите файл учёта вместе с исходным проектом, чтобы сохранить накопленные данные. Копия игры с новым `projectId` начинает новый учёт; обычный ZIP проекта не включает этот локальный журнал. На Pages публикуются только агрегаты: модели, проценты, счётчики и время последней учтённой записи. ID чатов, ходы, ID запросов и пути не публикуются. Сборка игры не включает этот файл.

JSONL — локальный формат Codex, который может меняться. Неподдерживаемые записи не заменяются оценками. [Официальная документация Codex App Server](https://learn.chatgpt.com/docs/app-server#turn-events) описывает уведомления `thread/tokenUsage/updated` и `model/rerouted`; текущая реализация читает сохранённые записи установленного приложения без запуска дополнительного агента.
