# Выпуск игры и обновление каталога

Каталог: [Shelter Arcade](https://gadaev-sergey.github.io/shelter-arcade/). Правила работы агента: [shelter-game-release](../../skills/shelter-game-release/SKILL.md).

Готовая игра или играбельный прототип, новая функция и исправление игрового бага завершаются публикацией игры и обновлением её карточки. Для задачи, явно ограниченной локальной работой, публикация не выполняется.

Перед началом каждого хода разработки выполните `npm run usage:begin -- games/<id>`, чтобы учесть реальные токены и модели. [Подробности учёта](AI-USAGE.md).

После подходящих тестов и `npx tsc --noEmit` увеличьте `gameVersion` игры и выполните:

```sh
npm run release:game -- games/lumen
```

Команда сначала собирает самостоятельную игру, затем публикует её в репозиторий из `catalog/games.json`. После подтверждения нового SHA GitHub Pages обновляет версию и дату карточки и публикует каталог. Исходники движка и соседние проекты не отправляются. Новая игра получает отдельный публичный репозиторий; существующие ветки других проектов защищены маркером публикации.

Для новой игры заполните запись в `catalog/games.json`, используя действующую карточку как пример. Укажите её `projectId`, путь к проекту, будущие репозиторий и Pages URL, жанр, описание и настоящий снимок в `catalog/assets/`. Начальное `published: false` скрывает черновик; успешный выпуск делает его видимым. Статус `prototype` явно обозначает прототип. Карточки упорядочены как записи в реестре.

Описание, жанр, детали и превью редактируются в реестре и папке изображений. Опубликованные версия, дата и SHA записываются командой выпуска после успеха. Для обновления только страницы каталога:

```sh
npm run build:catalog
npm run publish:catalog
```

Исходники страницы: `catalog/index.template.html` и `catalog/style.css`. Результат: `artifacts/catalog/site/`. На сайт попадают HTML, CSS, изображения и публичная запись версий, но не пути локальных проектов и не токены.

После публикации проверьте запуск по публичной ссылке, новые функции, исправленный сценарий, загрузку ресурсов и переход с карточки. Если обновилась только игра, а каталог завершился ошибкой, исправьте причину и повторите `publish:catalog`; заново отправлять игру не нужно.

Авторизация использует уже подключённый GitHub на компьютере. Новые репозитории создаются только в аккаунте, совпадающем с владельцем в реестре. Учётные данные не сохраняются в исходниках или выпущенных файлах.
